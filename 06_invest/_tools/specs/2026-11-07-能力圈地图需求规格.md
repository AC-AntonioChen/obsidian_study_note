# 投资能力圈地图 · 需求规格说明书

- 日期：2026-11-07
- 状态：待用户评审
- 项目位置：`学习笔记/06_invest/`（Obsidian vault 内自包含）
- 分期：本文档覆盖 P0 全部需求，P1/P2 为规划性描述

---

## 1. 背景与问题

能力圈（Circle of Competence）是投资中最基础的个人纪律：只在真正理解的领域下判断。但"圈"通常只存在于感觉里，由此产生两种典型失效：

1. **自我高估**：在了解有限的行业做出了重判断（看过几篇报道就当作"熟悉"）；
2. **圈子空转**：反复研究已经掌握的行业，圈的边界从不扩张，空白区长期无人认领。

两种失效的根源相同：掌握程度没有被**外化、维护、定期审视**。

## 2. 目标与价值主张

把"我懂什么"变成一张**可维护的地图**：写行业笔记 → 顺手自评 → 看板自动聚合 → 定期看大图找盲区。

| # | 价值点 | 说明 |
|---|--------|------|
| V1 | 能力圈外化 | 决策前快速自查："这个标的所在的行业，我有几成把握？" |
| V2 | 防自我高估 | 0-5 等级锚点强制对照判据自评，分数来源透明可追溯 |
| V3 | 防知识过期 | `last_review` + 180 天规则，让"熟悉"不会悄悄退化为"曾经熟悉" |
| V4 | 研究资源分配 | 看板空白区 = 下一轮该读什么；核心区 = 该花时间维护深度的领域 |
| V5 | 与笔记复利绑定 | 行业笔记既是自评的锚也是证据，不引入额外记账负担 |
| V6 | 零迁移成本 | 全部资产在 vault 内，数据是普通 markdown，Obsidian/脚本/任何工具都能读 |

**非目标（明确不做）**：
- 不做自动化掌握度算法（用户已明确选择纯自评）；
- 不做本地常驻服务/Web 应用；
- 不新增 Obsidian 插件依赖（仅使用已安装的 Dataview）；
- 不追踪三级申万分类。

## 3. 用户与使用场景

**用户**：单一投资者（spec 作者本人），桌面端 Obsidian 为主。

| 场景 | 触发 | 动作 |
|------|------|------|
| S1 每周复盘 | 打开 Obsidian | 看总览页：矩阵变化、过期提醒 |
| S2 完成一次行业研究 | 写完笔记 | 属性面板改 `mastery`、`last_review`，正文追加跟踪记录 |
| S3 看研报/选股前 | 对某标的有兴趣 | 搜行业笔记，看自评等级与跟踪记录，决定投入多少注意力 |
| S4 季度审视 | 每季度一次 | 跑 `build_map.py` 刷新大图，规划下一轮研究主题 |

## 4. 总体架构

vault 内自包含，数据流单向：

```
行业笔记 frontmatter（唯一事实源）
        │
        ├──> 能力圈总览.md（Dataview 实时读取，桌面端渲染）
        └──> _tools/build_map.py（按需运行）──> 能力圈地图/capability-map.html
```

- 笔记的 YAML frontmatter 是唯一事实源；看板与 HTML 大图均为其派生视图；
- `_tools/` 下脚本仅用 Python 标准库，无第三方依赖；
- 大图为单文件 HTML（内联 CSS/JS，零网络依赖），浏览器直接打开。

## 5. 数据模型

### 5.1 目录结构

```
06_invest/
├── 能力圈总览.md            # FR-3 看板首页
├── 行业/                    # 165 个行业笔记，一二级平铺
│   ├── SW801010-农林牧渔.md
│   ├── SW801740-电力设备.md
│   └── SW801737-电池.md
├── 公司/                    # P1：公司研究笔记
├── 模板/
│   ├── tpl-行业.md
│   └── tpl-公司.md          # P1
├── 能力圈地图/
│   └── capability-map.html  # FR-4 生成器输出
└── _tools/
    ├── seed.py
    ├── build_map.py
    ├── sw_industries.py     # 申万分类清单（数据与逻辑分离）
    └── specs/               # 本规格文档
```

**约定**：
- 一、二级行业笔记平铺在 `行业/` 一个目录，父子关系由 frontmatter 表达；
- 文件名格式 `SW{六位代码}-{行业名}.md`，代码前缀保证文件树排序稳定；
- 公司笔记（P1）通过 `sw_l1`/`sw_l2` 字段挂到行业，行业页反向汇总。

### 5.2 行业笔记 frontmatter schema

| 字段 | 类型 | 适用 | 必填 | 说明 |
|------|------|------|------|------|
| `type` | text | 全部 | ✓ | 固定 `industry` |
| `name` | text | 全部 | ✓ | 行业名，如 `电池`（文件名含代码前缀，故单独存） |
| `sw_code` | text | 全部 | ✓ | 申万代码，**必须带引号**（`"801737"`），防被解析为数字 |
| `sw_l1` | text | 仅二级 | ✓ | 所属一级行业名；一级笔记无此字段 |
| `level` | number | 全部 | ✓ | `1` 或 `2` |
| `mastery` | number | 全部 | ✓ | 自评 0-5，见 §6 锚点 |
| `last_review` | date | 全部 | ✓ | 上次自评/回顾日期 `YYYY-MM-DD`；dataview 需 date 类型才能做时间比较 |
| `status` | text | 全部 | ✓ | `active`（在跟踪）/ `watching`（关注）/ `dormant`（搁置）；种子默认 `dormant` |

类型要求是硬约束：`mastery` 必须是 number、`last_review` 必须是 date，否则 Dataview 排序与时间比较失效。seed.py 与模板共同保证。

**一级 vs 二级的关系**：一级的 `mastery` 由用户独立自评（对行业的整体认知 ≠ 二级的算术平均）；二级均分在看板单列展示，两列互不覆盖。

### 5.3 二级均分口径

一级的"二级均分"只在 `mastery > 0` 的二级笔记上计算，并在看板同格显示覆盖数 `x/y`。全 0 的一级不显示均分（显示 `—`），避免空数据被误读成有分。

## 6. 掌握度评分体系（纯自评 + 锚点）

唯一评分字段 `mastery: 0-5`。锚点写死在模板内，自评时对照判据：

| 分值 | 等级 | 判据（满足才可打） |
|------|------|--------------------|
| 0 | 圈外 | 没研究过 |
| 1 | 听过 | 知道行业大概做什么，说不出细节 |
| 2 | 入门 | 读完过行业综述，能说出产业链主要环节和代表公司 |
| 3 | 熟悉 | 跟踪过 ≥1 个财报周期，理解商业模式与核心指标，能指出 2-3 家龙头的差异 |
| 4 | 深入 | 理解竞争格局、景气驱动、估值锚，能独立形成有依据的判断 |
| 5 | 核心 | 长期跟踪，判断有可验证记录，愿意真金白银表达观点 |

**降级是被鼓励的动作**：自评记录里写明升降级理由；过期提醒触发后若确认"记忆已失效"，应降级而非维持。

## 7. 功能需求

### FR-1 种子生成（P0）

- `seed.py` 依据 `sw_industries.py` 清单生成 31 个一级 + 约 134 个二级 = 165 个行业笔记；
- **幂等**：目标文件已存在则跳过且不覆盖（保护用户已编辑的笔记），输出统计"新建 x / 跳过 y"；
- 种子笔记初始 `mastery: 0`、`status: dormant`、`last_review` 为生成日；
- 运行方式：`python _tools/seed.py`（在 `06_invest` 目录下运行，相对路径定位）。

### FR-2 行业模板（P0）

- `模板/tpl-行业.md`：含 §5.2 完整 frontmatter 骨架（占位值）+ §6 等级锚点表 + 正文固定结构；
- 正文固定五段：**速览**（一句话说清这个行业）/ **产业链环节** / **竞争格局** / **跟踪记录**（时间线，`- YYYY-MM-DD 事件 :: [[相关笔记]]`）/ **自评记录**（何时、从几级到几级、为什么）；
- 一、二级共用同一模板（二级多填 `sw_l1`）。

### FR-3 in-vault 看板：能力圈总览.md（P0）

单页三个区块，dataviewjs 渲染：

1. **色块矩阵**：31 个一级行业一格一色，格内显示行业名 + mastery 数字，背景色按 §8.3 色板映射，点击格跳转行业笔记；默认按 mastery 降序（掌握的浮在最上面）；
2. **一级明细表**：行业（链接）｜自评｜覆盖 x/y｜二级均分｜最近回顾｜距今天数；
3. **过期提醒区**：`mastery >= 2 且 last_review 距今 > 180 天` 的行业清单（含二级），空状态显示"暂无过期项"。

页面顶部注明"dataviewjs 需桌面端渲染"。

### FR-4 HTML 大图：build_map.py → capability-map.html（P0）

单文件 HTML，三个视图（页内 tab 切换）：

| 视图 | 形态 | 用途 |
|------|------|------|
| V1 热力矩阵（主视图） | 行 = 31 一级（申万官方顺序，稳定不跳变），行内逐格铺开该一级下全部二级，色阶 = mastery，图例显示 0-5 色板 | 一眼看出圈的形状与边界 |
| V2 统计摘要 | 各等级行业数、一级/二级覆盖率、`mastery=0` 空白清单、过期清单 | 季度规划下一轮研究主题 |
| V3 圈层图 | 同心圆分层：5/4 在圆心，向外递减到 0 | 直观呈现"边界" |

技术约束：内联 CSS/JS、无 CDN、无网络请求，文件体积 < 200KB；输出路径 `能力圈地图/capability-map.html`，重复运行直接覆盖；在总览页放一个指向它的链接（Obsidian 中点击后由系统浏览器打开）。

### FR-5 自评维护流（P0，UX 约定）

唯一的日常维护动作：属性面板改 `mastery` 与 `last_review` 两个属性 + 正文追加自评记录一行。规格不新增任何表单/命令，一切依赖 Obsidian 原生属性编辑。

### FR-6 公司笔记与行业反查（P1）

- `模板/tpl-公司.md`：frontmatter 含 `type: company`、`sw_l1`、`sw_l2`、`ticker`（可选）；
- 行业页通过 Dataview 反向汇总"该行业下我研究过哪些公司"（数量 + 列表），在看板一级明细表中显示公司笔记数列。

### FR-7 与 ZCode 联动 / 持仓交叉视图（P2，规划性）

- 研报/点评类工作流完成后自动更新对应行业的 `last_review`（只动时间戳，不改自评分）；
- 持仓行业 × 能力圈交叉视图："你重仓的行业在不在你圈里"。

## 8. 种子数据与视觉规格

### 8.1 申万分类清单（sw_industries.py）

- 口径：申万 2021 版，31 个一级 + 134 个二级（以清单实际条数为准）；
- 数据结构：`[{"l1": "电力设备", "l1_code": "801740", "l2": [("电池", "801737"), ...]}, ...]`；
- **准确性约定**：行业名称以官方口径为准；个别二级代码如与官方有出入，以名称为准、代码不阻断交付，交付前用行情数据服务校准一次并回填。

### 8.2 过期规则

`mastery >= 2 且 last_review 距今 > 180 天` → 列入过期清单。阈值 180 天为常量，定义在 `_tools/` 单一位置，看板与大图共用同一数值。阈值取 180 而非 90：入门知识也会过期，但不值得 90 天的高频提醒噪音。

### 8.3 mastery 色板（看板与大图共用）

| mastery | 颜色 | hex |
|---------|------|-----|
| 0 圈外 | 浅灰 | `#E8E8E8` |
| 1 听过 | 红 | `#EF9A9A` |
| 2 入门 | 橙 | `#FFCC80` |
| 3 熟悉 | 黄 | `#FFF59D` |
| 4 深入 | 浅绿 | `#A5D6A7` |
| 5 核心 | 绿 | `#66BB6A` |

文字统一深色 `#333`；色板定义为常量，HTML 与 dataviewjs 各自内置一份相同值（规格在此处为唯一出处）。

## 9. 非功能需求

| # | 需求 |
|---|------|
| NFR-1 | 脚本仅依赖 Python 3 标准库；frontmatter 解析为手写轻量解析器（只处理模板产出的扁平 `key: value`，不支持嵌套/多行），避免 PyYAML 依赖 |
| NFR-2 | 所有文件读写显式 `encoding='utf-8'`（Windows 中文路径 + Git Bash 环境） |
| NFR-3 | 不破坏 vault 的 git 同步（obsidian-git）：所有产出为普通文件，无符号链接、无外部路径引用 |
| NFR-4 | Dataview 兼容：frontmatter 字段类型严格符合 §5.2（number/date/text） |
| NFR-5 | 移动端降级可接受：正文与 frontmatter 可读；dataviewjs 看板仅桌面渲染，HTML 大图移动浏览器可打开 |
| NFR-6 | digitalgarden 不发布项目文件：项目文件不带 `dg-publish` 属性，遵循插件默认不发布 |
| NFR-7 | 性能：165 篇笔记量级下看板与脚本均应秒级完成，不做缓存层 |

## 10. 验收标准（P0）

1. 在 `06_invest` 下运行 `python _tools/seed.py`：`行业/` 生成 165 篇笔记（31 一级 + 清单实际二级数）；重复运行输出"跳过 165"，不覆盖任何已编辑内容；
2. 任意修改一篇行业笔记的 `mastery`，`能力圈总览.md` 的矩阵与明细表即时反映（桌面端 Dataview）；
3. `last_review` 改为 180 天前且 `mastery >= 2` 的笔记出现在过期提醒区；`mastery=1` 的同日期笔记不出现；
4. 运行 `python _tools/build_map.py`：生成单文件 `capability-map.html`，浏览器离线打开可见热力矩阵 + 统计摘要 + 圈层图三视图，数据与 frontmatter 一致（抽 3 个行业人工核对）；
5. 全部行业笔记可被 Dataview 查询：`mastery` 可排序、`last_review` 可做日期比较（类型正确）；
6. `tpl-行业.md` 中包含完整等级锚点表，新建笔记粘贴模板后无需再查文档。

## 11. 风险与开放问题

| # | 风险/问题 | 处置 |
|---|-----------|------|
| R1 | 申万二级代码与官方清单有出入 | 名称优先、代码不阻断；交付前用行情数据服务校准一次 |

**开放问题**（实现前可定，不阻塞规格）：
- Q1：总览页是否需要"上次大图生成日期"显示（可在 HTML 中内嵌生成时间戳，总览页读取）→ 默认做，成本极低；
- Q2：二级笔记是否需要单独的看板钻取页 → P0 不做，一级明细表已含二级覆盖统计，钻取走行业笔记正文。

## 12. 术语

- **申万分类**：申万宏源发布的 A 股行业分类标准，2021 版含 31 个一级行业、134 个二级行业；
